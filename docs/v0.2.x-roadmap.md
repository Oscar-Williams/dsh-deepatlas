# DeepAtlas v0.2.x 路线图

DeepAtlas 在可预见的开发周期内持续使用 `v0.2.x` 版本线。稳定版按 `v0.2.3`、`v0.2.4`、`v0.2.5`、`v0.2.6`……依次发布；范围较大的里程碑使用多个 `rc.x` 分段验收。版本号跟随已交付范围与 Gate 结果，不限定 v0.2.x 的后续数量。

产品定位随 DSH 生态成熟度聚焦为 **本地能力保障层（Capability Assurance）**。DeepAtlas 结合当前任务、profile、DSH/Node 版本与已安装组合，给出能力缺口诊断，并以可持久化的 Capability Change Transaction 证明一次能力变更的来源、运行时差异、目标验收结果和恢复路径。生态发现继续承担候选输入，产品价值以本机可验证结论、可复现变更和可撤销结果衡量。

## 发布原则

1. `main` 始终保留可安装、可回归的稳定状态；功能分支使用单一里程碑和清晰的验收清单。
2. RC 包含完整构建产物、迁移路径、冻结数据和可重放验证记录；稳定标签在对应 RC Gate 全部通过后创建。
3. 公开 tag 保持不可变。发布修正通过后续 v0.2.x 补丁版本承接。
4. README、CHANGELOG、兼容矩阵、GitHub Release、`package.json` 和已构建 `lib/` 在发布提交中保持一致。
5. DSH 兼容结论来自 Windows/Linux、Node 22/24、profile 组合、六工具 smoke 与真实启动验证。

## 近期发布列车

### v0.2.3：Evidence v2

- `v0.2.3-rc.1`：provenance schema、事实 atom、claim、中央 resolver、旧索引迁移和结构 Gate。
- 后续 RC：补齐 publisher manifest、README 与入口文件的 commit-pinned provenance；完成结构化否定、冲突、supersede、顺序无关合并和 byte-stable 输出。
- 稳定 Gate：gold fixture、accepted precision、retrieval fallback、PluginRecord 与审计共享事实、原生 v2 全量扫描，以及 `legacy-partial` 退出条件全部通过。

### v0.2.4：Capability Diagnosis、HostIntentGate 与任务觉察

- 冻结 30 个意图 × 4 种改写，共 120 条；覆盖规范 capability 和 no-tool 负向组。
- 记录 DSH durable session 中的 tool call、schema invalid、超时和无调用终态，生成脱敏 JSONL、manifest、JUnit、摘要、混淆矩阵和延迟报告。
- PR CI 使用无密钥 replay；经单独授权的 live gate 固定 DSH、provider 和模型版本。
- 稳定 Gate 报告 accuracy、micro/macro-F1、exact-set、一致率、false-call、forbidden capability、mustNot 和 integrated Top3-SA。
- 诊断结果区分能力已具备、已安装但配置未生效、版本或组合不兼容、可由现有工具完成、确有新增插件需求五类状态。
- 在 DSH 提供稳定生命周期接口的 profile 中接入任务觉察：会话开始同步索引状态，步骤前读取裁剪后的任务上下文，工具失败或阶段变化时重新评估。自动行为限于本地诊断与建议；扫描、审计、安装继续沿用确认与授权边界。

### v0.2.5：Capability Change Transaction

v0.2.5 交付完整的纵向事务，覆盖 `before fingerprint → exact candidate → structural preflight → shadow boot → runtime delta → goal acceptance → policy verdict → rollback artifact → after fingerprint → receipt`。多个 RC 用于分段验证，稳定版以整条链路可重放为发布条件。

- `rc.1`：冻结 `GoalContract`、`CapabilityChangeCandidate`、规范化 fingerprint、事务状态机与 receipt schema；GitHub commit、npm integrity、SkillHub install plan 和本地 artifact 共用候选身份接口。
- `rc.2`：在受控临时 `DSH_HOME`、profile 副本和独立端口完成 Resolved Environment Preflight 与真实 shadow boot；采集 pnpm/npm resolved graph、realpath、peer/mixed-RC、module exports/entry resolve、完整 loader tree，以及 tools、services、routes、permissions、prompts 和 resources 的注册差异。
- `rc.3`：比较 declared、inferred、realized 与 task-required capability，执行分层 acceptance probes，生成确定性 policy verdict、可恢复 artifact、安装后 fingerprint 和内容寻址 receipt；现场安装继续绑定用户授权。
- 稳定 Gate：同一事务可在 Windows/WSL 重放；volatile 字段规范化后 receipt byte-stable；shadow 与现场组合的 parity 可量化；缺失发布文件、dependency closure 缺层、mixed RC、模块 shadowing、export mismatch 与启动/注册失败均有冻结 fixture；失败注入能够恢复已知良好状态；目标验收、权限增量和回滚结果均有独立事实。

### v0.2.6：Transaction Hardening 与 DSH 适配

- 扩展 GitHub、npm、SkillHub 和本地包适配器，统一来源身份、下载完整性与供应链证据。
- 接入 DSH 可用的 safe-boot、recoverable bundle 或 doctor 能力，通过 feature detection 选择宿主接口；缺少稳定接口时沿用隔离进程适配层。
- 强化 Dependency Drift Detector 与 Capability Reality Check，兼容 Capmark/CAP、DSH capability declaration 和其他来源格式，同时保留来源 authority 与推断证据。
- 覆盖 restart、dispose、HMR、native ABI、端口、凭据缺失和网络受限等故障注入；形成 receipt replay 与恢复 SLO。

### v0.2.7：Active Assurance 与因果追踪

- 在任务中以冷却、去重、隐私裁剪和置信阈值控制主动建议；任务阶段变化或工具失败时重新诊断能力缺口。
- 安装后重放目标验收，持续比较 runtime registration 与 profile fingerprint；退化结论关联最近一次 receipt，并给出可验证的恢复方案。

### v0.2.8：团队策略与可移植证明

- 为团队和 CI 提供 policy bundle、receipt 签名/验证、离线复核、审批记录和可移植验证胶囊。
- 区分构建者、审阅者、安装者和运行环境的信任边界，支持组织级 mustNot、权限预算与来源策略。

### v0.2.9：Verified Installability 与生态协议

- 将生态覆盖转化为 Verified Installability、Pinned Publisher Coverage、Shadow Boot Pass、Runtime Registration Accuracy、Goal Acceptance Pass、Rollback Success 和 Receipt Replay Success 等指标。
- 推动与 DSH capability declaration、doctor/safe-boot 以及第三方目录的互操作协议，让目录提供候选、宿主提供运行接口、DeepAtlas 提供本机事务证明。

## 后续 v0.2.x

v0.2.10 及更高版本根据 DSH 的实际发布节奏滚动规划，技术主题包括：

- 新 DSH RC 或稳定接口的 compatibility canary 与支持窗口；
- 索引 schema 和本地数据的可恢复迁移；
- 审计规则、来源信誉、签名与供应链证据；
- 检索、组合建议和解释质量的冻结 Gate；
- 安全响应、弃用周期、发布 SLO 与维护者手册；
- Node、TypeScript、Vitest、Vite 等工具链的受控升级。
- Capability Change Transaction 的性能、并发控制、长期 receipt 保存和隐私治理。

新范围进入最近一个合适的 v0.2.x milestone，并在发布前冻结验收条件。长期规划保留连续性，也允许 DSH 的接口和生态变化重新调整优先级。

## 与 DSH 发布协同

| 通道 | 用途 | 策略 |
|---|---|---|
| tested | 日常 CI 的已验证 DSH 版本 | 固定确切版本，保证可重复性 |
| next | DSH 新 RC canary | 定时读取 `dist-tags.next`，与 tested 去重后运行 |
| manual | 维护者指定版本 | 用于预发布、回归定位和兼容性复核 |

新 DSH 版本先经过 24–72 小时 canary。通过后更新 `docs/compatibility.md`、README 徽章和发布说明；失败时保存 CLI capture 与复现信息，继续维持上一已验证版本的稳定安装路径。Core 提供 recoverable bundle、doctor 或 capability declaration 时，DeepAtlas 通过适配器复用这些宿主事实，并继续负责目标契约、运行时差异、策略判定与事务 receipt。

## 持续成熟度 Gate

- 发布载荷可从公开 tag 在全新环境安装并启动。
- 源码、构建产物、锁文件和包元数据一致。
- 索引与审计 schema 具备版本化迁移和恢复路径。
- 安装保持 commit 绑定审计、明确授权、快照、组合验证和回滚。
- 评测区分宿主模型意图选择、确定性检索、顾问安全和证据质量。
- 能力变更评测区分结构可组合、shadow 可启动、运行时注册符合预期、目标验收通过和恢复可重放。
- 兼容矩阵、支持窗口、弃用安排和安全响应流程均有可复核记录。
